A mesma função tradicional:

            return a + b;
            

            }

Pode ser escrita como:

            return a + b;
            

            };

Quando a função possui apenas uma expressão que será retornada, podemos simplificá-la ainda mais.

Isso equivale a:

const dobrar = (numero) => numero * 2;

As duas formas são válidas.

📚 Arrays e métodos úteis

Arrays são estruturas usadas para guardar vários valores dentro de uma única variável. 

const nomes = [
            'João',
            'Maria',
            'Carlos'
            

            ];

O JavaScript possui vários métodos para trabalhar com esses valores. Alguns dos mais importantes são forEach(), map(), filter() e find().

🔁 forEach()

Executa uma função para cada item do array. 

const nomes = ['João', 'Maria', 'Carlos'];
            

            nomes.forEach((nome) => {

            Maria
            Carlos

O forEach() é muito útil quando queremos simplesmente executar alguma ação para cada elemento.

⚠️ Importante

O forEach() não é utilizado para criar um novo array com os resultados.

🗺️ map()

O map() percorre o array e cria um novo array com o resultado da transformação de cada item.

            console.log(dobrados);

⚠️ Erro comum

Um erro bastante comum é usar map() quando queremos apenas executar uma ação.

Por exemplo: 

nomes.map((nome) => {

            console.log(nome);
            

            });

Se não precisamos do novo array, o mais apropriado é: 

nomes.forEach((nome) => {

            console.log(nome);
            

            });

Outra confusão comum é usar filter() esperando receber um único objeto. O filter() sempre retorna um array, mesmo que encontre apenas um elemento. 

const resultado = lista.filter(...);
            

            console.log(resultado);
            // → array

Se queremos apenas o primeiro resultado, normalmente usamos find().

🎯 Selecionando elementos HTML

Para o JavaScript interagir com um elemento HTML, primeiro precisamos encontrá-lo.

Existem várias formas de fazer isso. No código moderno, querySelector() e querySelectorAll() são especialmente úteis porque utilizam seletores CSS.

🎯 querySelector()

Seleciona o primeiro elemento que corresponde ao seletor informado. 

const botao = document.querySelector('#salvar');

Se temos: 

<button id="salvar">Salvar</button>

O JavaScript encontra esse botão através do seu id.

🔵 ID

document.querySelector('#salvar');

O # indica que estamos procurando um id.

🟢 Classe

document.querySelector('.botao-salvar');

O . indica uma classe. 

<button class="botao-salvar">
            Salvar

🏷️ Tag

document.querySelector('button');

Também podemos procurar diretamente pelo nome da tag.

Porém, como querySelector() retorna apenas o primeiro resultado, se houver vários botões ele pegará somente o primeiro.

🎯 Seletores mais específicos

Como querySelector() utiliza seletores CSS, podemos combinar seletores. 

document.querySelector('#formulario .botao-salvar');

Nesse caso estamos procurando um elemento com a classe botao-salvar que esteja dentro do elemento com o ID formulario.

📚 querySelectorAll()

Enquanto querySelector() pega o primeiro elemento, querySelectorAll() pega todos os elementos correspondentes. 

const botoes = document.querySelectorAll('.botao');

Se existirem vários elementos: 

<button class="botao">Salvar</button>

O JavaScript terá uma coleção contendo os três elementos.

🔁 Percorrendo vários elementos

const botoes = document.querySelectorAll('.botao');


            botoes.forEach((botao) => {


            console.log(botao);


            });

Aqui aparece novamente uma Arrow Function: 

(botao) => {

            console.log(botao);


            }

O forEach() executa a função uma vez para cada elemento encontrado.

🆔 getElementById()

Existe também uma forma específica para buscar elementos pelo ID: 

const botao = document.getElementById('salvar');

Nesse caso não usamos #.

Isso: 

document.getElementById('salvar');

equivale, na prática, a: 

document.querySelector('#salvar');

Primeiro elemento:

            document.querySelectorAll('.classe');

            Pelo ID:

            document.getElementById('id');

🖱️ Eventos e addEventListener()

Um evento é uma ação que acontece na página. Por exemplo: clicar em um botão, enviar um formulário, alterar um campo, passar o mouse ou pressionar uma tecla.

O JavaScript pode "escutar" esses eventos e executar alguma ação quando eles acontecerem.

👂 addEventListener()

elemento.addEventListener('evento', funcao);

Podemos interpretar assim: 

elemento
            ↓
            

            quem vamos observar

            'evento'
            ↓
            o que estamos esperando acontecer

            funcao
            ↓
            o que devemos fazer quando acontecer

🖱️ Exemplo com clique

HTML: 

<button id="salvar">Salvar</button>

JavaScript: 

const botao = document.querySelector('#salvar');
            

            botao.addEventListener('click', () => {

            
            console.log('O botão foi clicado!');
            

            });

Nesse exemplo, o JavaScript encontra o botão e fica esperando o evento click.

Quando o usuário clicar, a Arrow Function será executada.

⚡ Forma de pensar

Quando
            ↓
            

            o botão receber um
            ↓
            click
            ↓
            faça isso

🧩 Função separada

A função não precisa necessariamente ficar diretamente dentro do addEventListener(). 

function salvar() {

            console.log('Salvando...');
            

            }

            const botao = document.querySelector('#salvar');

            botao.addEventListener('click', salvar);

Aqui passamos a função sem colocar () depois do nome. 

botao.addEventListener('click', salvar);

Não fazemos: 

botao.addEventListener('click', salvar());

Porque salvar() executaria a função imediatamente, em vez de esperar o clique.

📝 Evento de formulário — submit

Para formulários, um dos eventos mais importantes é submit. 

const formulario = document.querySelector('#formulario');
            

            formulario.addEventListener('submit', (event) => {

            
            event.preventDefault();

            console.log('Formulário enviado!');
            

            });

🛑 preventDefault()

event.preventDefault();

Impede o comportamento padrão daquele evento.

Em um formulário HTML, o comportamento padrão normalmente envolve o navegador enviar o formulário e recarregar ou navegar para outra página.

No GatMan, podemos impedir esse comportamento para que o JavaScript possa enviar os dados usando fetch().

📦 O objeto event

formulario.addEventListener('submit', (event) => {

            console.log(event);
            

            });

O parâmetro event contém informações sobre o evento que aconteceu.

Podemos dar outro nome para ele: 

formulario.addEventListener('submit', (e) => {

            e.preventDefault();
            

            });

event e e são apenas nomes de variáveis. O nome não muda o funcionamento.

event.target.value

🖥️ Manipulando o HTML (DOM)

DOM significa Document Object Model. É a representação da página HTML que o JavaScript consegue acessar e modificar.

Em termos simples: 

HTML
            

            ↓
            DOM
            ↓
            JavaScript
            ↓
            altera a página

🎯 Selecionar um elemento

const titulo = document.querySelector('#titulo');

Depois de guardar o elemento em uma variável, podemos trabalhar com ele.

📝 textContent

textContent permite ler ou alterar o texto de um elemento. 

const titulo = document.querySelector('#titulo');
            

            titulo.textContent = 'Novo título';

HTML: 

<h2 id="titulo">Título antigo</h2>

Depois do JavaScript: 

<h2 id="titulo">Novo título</h2>

📖 innerHTML

innerHTML permite alterar o conteúdo HTML que está dentro de um elemento. 

const mensagem = document.querySelector('#mensagem');
            

            mensagem.innerHTML = 'Salvo com sucesso!';

A diferença principal: 

textContent
            

            ↓
            trata como texto

            innerHTML
            ↓
            interpreta HTML

⚠️ Cuidado com innerHTML

Evite colocar diretamente no innerHTML conteúdo que veio de usuários ou de fontes não confiáveis. Para simplesmente alterar texto, prefira textContent.

📥 value

Para campos de formulário, usamos principalmente value para acessar ou alterar o valor. 

const nome = document.querySelector('#nome');
            

            console.log(nome.value);

Para alterar: 

nome.value = 'Wagner';

Exemplo: 

<input
            type="text"
            id="nome"
            

            >

🧹 Limpando um formulário

Podemos limpar um campo individual: 

campo.value = '';

Ou podemos limpar o formulário inteiro usando reset(). 

formulario.reset();

Isso é muito útil depois que um cadastro foi salvo com sucesso.

👁️ Mostrar e esconder elementos

Podemos acessar o estilo de um elemento através de style. 

const mensagem = document.querySelector('#mensagem');
            

            mensagem.style.display = 'none';

Para mostrar novamente: 

mensagem.style.display = 'block';

⚠️ Mas existe uma forma melhor

Em projetos maiores, normalmente é melhor controlar a aparência através de classes CSS em vez de colocar estilos diretamente no JavaScript.

🎨 classList

classList permite adicionar, remover e verificar classes CSS.

Adicionar classe

elemento.classList.add('ativo');

Remover classe

elemento.classList.remove('ativo');

Alternar classe

elemento.classList.toggle('ativo');

O toggle() adiciona a classe se ela não existir e remove se ela já existir.

Verificar classe

elemento.classList.contains('ativo');

Retorna true ou false.

🔗 Atributos

Podemos ler ou alterar atributos HTML usando getAttribute() e setAttribute().

Ler atributo

const imagem = document.querySelector('#foto');
            

            const caminho = imagem.getAttribute('src');

Alterar atributo

imagem.setAttribute('src', 'nova-foto.jpg');

🆕 Criar elementos

O JavaScript também pode criar novos elementos HTML. 

const novoParagrafo = document.createElement('p');
            

            novoParagrafo.textContent = 'Novo texto';

Criar o elemento não significa que ele já apareceu na página. Precisamos adicioná-lo ao DOM. 

document.body.appendChild(novoParagrafo);

➕ append()

Podemos adicionar conteúdo dentro de um elemento utilizando append(). 

const lista = document.querySelector('#lista');
            

            const item = document.createElement('li');

            item.textContent = 'Novo item';

            lista.append(item);

🗑️ Remover elemento

Um elemento pode ser removido usando remove(). 

const mensagem = document.querySelector('#mensagem');
            

            mensagem.remove();

📤 Enviando dados para o PHP

Depois de aprender a encontrar elementos e reagir aos eventos, podemos fazer o JavaScript conversar com o PHP.

No GatMan, um dos principais mecanismos para isso é o fetch().

🌐 O que é fetch()?

fetch() permite fazer uma requisição HTTP para outro arquivo ou endereço.

Na prática, podemos usar o JavaScript para enviar dados para um arquivo PHP sem precisar recarregar a página. 

JavaScript
            ↓
            

            fetch()
            ↓
            salvar.php
            ↓
            Banco de dados

📝 Exemplo completo

HTML: 

<form id="formulario">

            <input type="text" name="andar">

Muitas operações em JavaScript não terminam imediatamente. Por exemplo, uma requisição fetch() pode precisar de algum tempo para chegar ao servidor e receber uma resposta.

⏳ O que significa assíncrono?

Uma operação assíncrona é uma operação que pode continuar acontecendo enquanto o restante da aplicação aguarda o resultado.

Quando colocamos async antes de uma função, estamos indicando que aquela função trabalha de forma assíncrona e poderá utilizar await.

                    (coluna1, coluna2, coluna3)

                VALUES
                    (?, ?, ?);

Primeiro informamos a tabela e as colunas. Depois informamos os valores que serão inseridos.

❓ Os ? do SQL

VALUES (?, ?, ?, ?, ?, ?, ?, ?)

Os ? são placeholders.

Eles representam os valores que serão enviados posteriormente.

Isso permite utilizar consultas preparadas com PDO, evitando colocar diretamente os valores enviados pelo usuário dentro do SQL.

Exemplo

$sql = "INSERT INTO tabela
                        (nome, idade)
                        VALUES (?, ?)";

Depois: 

$stmt->execute([
                    $nome,
                    $idade
                ]);

O primeiro valor vai para o primeiro ?, o segundo para o segundo, e assim por diante.

🛠️ prepare()

$stmt = $pdo->prepare($sql);

O que faz?

Prepara a consulta SQL para ser executada. 

$pdo
                ↓
                conexão com o banco

                prepare()
                ↓
                prepara o SQL

                $stmt
                ↓
                consulta preparada

▶️ execute()

$stmt->execute([
                    $andar,
                    $setor,
                    $item,
                    $status,
                    $modelo,
                    $observacoes,
                    $data_manutencao,
                    $usuario
                ]);

O que faz?

Executa a consulta preparada e envia os valores correspondentes aos ?.

🧠 A sequência

$sql
                ↓
                define o SQL

                $pdo->prepare($sql)
                ↓
                prepara

                $stmt->execute([...])
                ↓
                executa

✅ Retornando sucesso

echo json_encode([
                    'sucesso' => true,
                    'mensagem' => 'Inspeção de segurança salva com sucesso!'
                ]);

Depois de salvar o registro, o PHP envia uma resposta para o JavaScript.

O JavaScript poderá verificar: 

sucesso = true

e então mostrar uma mensagem para o usuário.

🚨 Tratando erros do banco

catch (PDOException $e) {

                    echo json_encode([
                        'sucesso' => false,
                        'mensagem' => 'Erro ao salvar a inspeção.',
                        'erro' => $e->getMessage()
                    ]);

                }

O que é PDOException?

É uma exceção relacionada ao PDO, utilizada para capturar erros relacionados à operação com o banco.

E o $e?

É o objeto que contém informações sobre o erro. 

$e->getMessage()

retorna a mensagem do erro.

⚠️ Atenção

Durante desenvolvimento, visualizar a mensagem do erro pode ser útil. Em produção, normalmente não devemos expor detalhes internos do banco diretamente para o usuário.

✏️ Editar dados — UPDATE

Para editar um registro existente no banco de dados, usamos o comando UPDATE.

No PHP, a lógica é muito parecida com o INSERT. A principal diferença é que agora precisamos informar qual registro será alterado.

🧠 Estrutura básica

UPDATE tabela
            SET coluna = ?
            WHERE id = ?;

1️⃣ Receber os dados

$id = $_POST['id'] ?? '';
            $status = $_POST['status'] ?? '';
            $observacoes = $_POST['observacoes'] ?? '';

O PHP recebe o id do registro que queremos alterar e os novos valores.

2️⃣ Criar o SQL

$sql = "UPDATE inspecao_seguranca
                    SET status = ?, observacoes = ?
                    WHERE id = ?";

3️⃣ Preparar

$stmt = $pdo->prepare($sql);

4️⃣ Executar

$stmt->execute([
                $status,
                $observacoes,
                $id
            ]);

⚠️ O WHERE é obrigatório na prática

UPDATE inspecao_seguranca
            SET status = 'Concluído';

Sem WHERE, o comando altera todos os registros.

Para editar somente um registro: 

UPDATE inspecao_seguranca
            SET status = 'Concluído'
            WHERE id = 15;

Como criar uma tabela

O comando CREATE TABLE é utilizado para criar uma nova tabela no banco de dados.

Exemplo:

CREATE TABLE inspecao_seguranca (

                id INT AUTO_INCREMENT PRIMARY KEY,

                andar VARCHAR(20) NOT NULL,

                setor VARCHAR(30) NOT NULL,

                item VARCHAR(100) NOT NULL,

                status VARCHAR(20) NOT NULL,

                modelo VARCHAR(50) DEFAULT NULL,

                observacoes TEXT DEFAULT NULL,

                data_manutencao DATE DEFAULT NULL,

                data_inspecao DATETIME DEFAULT CURRENT_TIMESTAMP,

                usuario VARCHAR(100) NOT NULL

            );

Tipos de dados

Quando criamos uma tabela, cada coluna precisa informar que tipo de informação ela poderá armazenar.

Os tipos mais usados no GatMan são:

INT

O que é?

Armazena números inteiros, ou seja, números sem casas decimais.

Quando usar?

Para IDs, quantidades, contadores e outros valores inteiros.

Exemplo:

id INT

Pode armazenar valores como: 

1
            25
            100
            5000

Erro comum:

Usar VARCHAR para números que serão utilizados matematicamente.

Dica:

Se é realmente um número e você precisará fazer cálculos com ele, considere usar um tipo numérico.

VARCHAR

O que é?

Armazena texto de tamanho variável.

O que significa o número?

VARCHAR(100)

O número entre parênteses define o limite de caracteres que a coluna pode armazenar.

Portanto: 

VARCHAR(20)

significa que o campo pode armazenar até 20 caracteres.

Quando usar?

Para textos relativamente curtos, como:

  • Nome
  • Setor
  • Status
  • Modelo
  • Usuário
  • Telefone

Exemplo:

setor VARCHAR(30)

Erro comum:

Colocar um tamanho muito pequeno para o conteúdo esperado.

Por exemplo: 

nome VARCHAR(5)

seria inadequado para nomes comuns.

Dica:

Não precisa colocar um número gigantesco sem motivo. Pense no maior conteúdo que aquela coluna realmente precisa armazenar.

TEXT

O que é?

Armazena textos maiores.

Quando usar?

Para campos como observações, descrições, comentários e textos que podem variar bastante de tamanho.

Exemplo:

observacoes TEXT

Por que não usar VARCHAR para tudo?

Porque nem todo texto possui o mesmo tamanho ou finalidade. Para textos maiores, TEXT pode representar melhor a intenção da coluna.

Erro comum:

Usar TEXT para absolutamente todos os textos, mesmo quando um VARCHAR seria mais apropriado.

Dica:

Pense em VARCHAR para textos curtos e TEXT para textos maiores.

DATE

O que é?

Armazena somente uma data.

Formato:

AAAA-MM-DD

Exemplo:

2026-08-16

Quando usar?

Quando a hora não é importante.

Por exemplo: 

data_manutencao DATE

Erro comum:

Usar DATETIME quando você só precisa da data.

Dica:

Se você precisa saber somente "qual dia?", DATE normalmente é suficiente.

DATETIME

O que é?

Armazena data e hora.

Exemplo:

2026-08-16 11:30:45

Quando usar?

Quando é importante saber exatamente quando algo aconteceu.

No GatMan, por exemplo: 

data_inspecao DATETIME

Erro comum:

Usar DATE quando a hora também é necessária.

Dica:

DATE = data.
DATETIME = data + hora.

Regras das colunas

Além do tipo de dado, podemos definir regras para determinar como aquela coluna poderá ser preenchida.

NOT NULL

O que é?

Determina que a coluna não pode receber NULL.

Em outras palavras:

O valor é obrigatório.

Exemplo:

usuario VARCHAR(100) NOT NULL

Quando usar?

Quando o registro não faz sentido sem aquela informação.

Exemplo no GatMan:

item VARCHAR(100) NOT NULL

Uma inspeção precisa saber qual item está sendo inspecionado.

Erro comum:

Tornar absolutamente todas as colunas obrigatórias, mesmo quando algumas informações são opcionais.

Dica:

Pergunte: "Esse campo realmente precisa existir em todo registro?"

NULL

O que é?

Representa a ausência de um valor.

NULL não significa exatamente a mesma coisa que vazio.

Exemplo:

modelo VARCHAR(50) DEFAULT NULL

Significa que uma inspeção pode não ter um modelo informado.

Quando usar?

Quando determinada informação é realmente opcional.

Erro comum:

Confundir: 

NULL
            ''
            0

Esses valores possuem significados diferentes.

DEFAULT

O que é?

Define um valor padrão para a coluna quando nenhum valor é informado.

Exemplo:

status VARCHAR(20)
            DEFAULT 'Pendente'

Se o INSERT não informar o status, o banco poderá utilizar automaticamente Pendente.

Outro exemplo:

data_inspecao DATETIME
            DEFAULT CURRENT_TIMESTAMP

Nesse caso, o banco registra automaticamente a data e hora da inserção.

Dica:

DEFAULT é muito útil para valores automáticos.

AUTO_INCREMENT

O que é?

Faz o banco gerar automaticamente o próximo número para aquela coluna.

Exemplo:

id INT AUTO_INCREMENT

Os registros poderão receber: 

1
            2
            3
            4
            5

Quando usar?

É muito comum utilizar em IDs numéricos.

Erro comum:

Tentar informar manualmente o ID em todas as inserções quando o banco já está configurado para gerar o valor.

Dica:

Normalmente aparece junto com PRIMARY KEY.

PRIMARY KEY

O que é?

Define a chave principal da tabela.

Ela identifica de forma única cada registro.

Exemplo:

id INT AUTO_INCREMENT PRIMARY KEY

Na prática:

id
            ---
            1
            2
            3
            4

Cada registro possui seu próprio identificador.

Quando usar?

Praticamente toda tabela deve possuir uma forma de identificar seus registros de maneira única.

Erro comum:

Pensar que PRIMARY KEY significa apenas "primeira coluna".

Não é a posição da coluna que importa. É a função de identificação única.

Dica:

No GatMan, o padrão mais comum será: 

id INT AUTO_INCREMENT PRIMARY KEY

Engine — InnoDB

InnoDB

O que é?

É o mecanismo utilizado pelo MySQL/MariaDB para armazenar e gerenciar os dados da tabela.

Pense nele como o "motor" da tabela.

Exemplo:

CREATE TABLE exemplo (
                id INT AUTO_INCREMENT PRIMARY KEY,
                nome VARCHAR(100)
            ) ENGINE=InnoDB;

Por que usamos InnoDB?

Ele oferece recursos importantes para aplicações como o GatMan, incluindo transações e relacionamentos entre tabelas.

Quando usar?

Para as tabelas do GatMan, InnoDB é uma escolha adequada e normalmente será o padrão.

Erro comum:

Pensar que InnoDB é um tipo de dado como VARCHAR ou INT.

Não é. É o mecanismo de armazenamento da tabela.

Dica:

VARCHAR, INT e DATETIME definem os dados.

InnoDB define o mecanismo da tabela.

Como consultar dados

O comando principal para consultar informações no banco é o SELECT.

A partir dele podemos escolher quais colunas queremos ver, filtrar registros, ordenar resultados e limitar a quantidade de dados retornados.

SELECT *

O que é?

Retorna todas as colunas da tabela.

Exemplo:

SELECT *
            FROM inspecao_seguranca;

O que significa?

SELECT  → quero consultar
            *       → todas as colunas
            FROM    → de qual tabela?
            inspecao_seguranca → tabela escolhida

Quando usar?

É muito útil durante desenvolvimento e para verificar rapidamente todos os dados de uma tabela.

Quando evitar?

Em consultas definitivas de sistemas grandes, normalmente é melhor selecionar somente as colunas necessárias.

Erro comum:

Usar SELECT * em absolutamente todas as consultas, mesmo quando você só precisa de duas ou três colunas.

Dica:

Para testar rapidamente uma tabela, SELECT * é ótimo.

Selecionar colunas específicas

O que é?

Em vez de trazer todas as colunas, podemos escolher exatamente quais queremos consultar.

Exemplo:

SELECT
                andar,
                setor,
                item,
                status
            FROM inspecao_seguranca;

Quando usar?

Quando você sabe exatamente quais informações precisa.

Vantagem:

A consulta fica mais clara e evita trazer informações desnecessárias.

Erro comum:

Esquecer a vírgula entre as colunas. 

-- ERRADO

            SELECT
                andar
                setor
                item

O correto: 

SELECT
                andar,
                setor,
                item
            FROM inspecao_seguranca;

Dica:

Uma coluna por linha deixa consultas maiores muito mais fáceis de ler.

WHERE

O que é?

Permite definir uma condição para escolher quais registros serão retornados.

Exemplo:

SELECT *
            FROM inspecao_seguranca
            WHERE status = 'Pendente';

O que significa?

"Mostre os registros da tabela onde o status seja Pendente."

Quando usar?

Sempre que você não quiser retornar todos os registros.

Erro comum:

Esquecer as aspas ao comparar textos. 

-- ERRADO

            WHERE status = Pendente

O correto: 

WHERE status = 'Pendente'

Dica:

WHERE é uma das palavras mais importantes do SQL.

Pense: WHERE = onde / em quais condições?

Operadores de comparação

O WHERE pode utilizar diferentes operadores para criar condições.

Operador Significado Exemplo
= igual id = 5
!= diferente status != 'OK'
> maior que id > 10
< menor que id < 10
>= maior ou igual id >= 10
<= menor ou igual id <= 10

Exemplo:

SELECT *
            FROM inspecao_seguranca
            WHERE id > 10;

AND

O que é?

Permite exigir que duas ou mais condições sejam verdadeiras ao mesmo tempo.

Exemplo:

SELECT *
            FROM inspecao_seguranca
            WHERE andar = '1º Andar'
            AND status = 'Pendente';

O que significa?

O registro precisa estar no 1º Andar E ter status Pendente.

Dica:

Pense: AND = E.

OR

O que é?

Permite aceitar uma condição ou outra.

Exemplo:

SELECT *
            FROM inspecao_seguranca
            WHERE status = 'Pendente'
            OR status = 'Atenção';

O que significa?

Retorne registros que sejam Pendente OU Atenção.

Dica:

Pense: OR = OU.

ORDER BY

O que é?

Organiza os resultados da consulta.

Do menor para o maior:

SELECT *
            FROM inspecao_seguranca
            ORDER BY id ASC;

ASC significa crescente.

Do maior para o menor:

SELECT *
            FROM inspecao_seguranca
            ORDER BY id DESC;

DESC significa decrescente.

Exemplo muito usado no GatMan:

SELECT *
            FROM inspecao_seguranca
            ORDER BY data_inspecao DESC;

Assim os registros mais recentes aparecem primeiro.

Erro comum:

Confundir ASC e DESC.

Dica:

DESC é muito útil para históricos, porque normalmente queremos mostrar o mais recente primeiro.

LIMIT

O que é?

Limita a quantidade de registros retornados.

Exemplo:

SELECT *
            FROM inspecao_seguranca
            LIMIT 10;

Retorna no máximo 10 registros.

Combinando com ORDER BY:

SELECT *
            FROM inspecao_seguranca
            ORDER BY data_inspecao DESC
            LIMIT 10;

Retorna os 10 registros mais recentes.

Dica:

ORDER BY + LIMIT é uma combinação extremamente útil.

Combinando os comandos

Agora podemos juntar várias partes de uma consulta. 

SELECT
                id,
                andar,
                setor,
                item,
                status,
                data_inspecao

            FROM inspecao_seguranca

            WHERE status = 'Pendente'

            ORDER BY data_inspecao DESC

            LIMIT 10;

Como ler isso?

  1. SELECT → quais informações quero?
  2. FROM → de qual tabela?
  3. WHERE → quais registros?
  4. ORDER BY → em qual ordem?
  5. LIMIT → quantos quero receber?

🧠 Regra mental:

SELECT
                ↓
            O que quero ver?

            FROM
                ↓
            De onde?

            WHERE
                ↓
            Quais?

            ORDER BY
                ↓
            Em qual ordem?

            LIMIT
                ↓
            Quantos?

Como alterar dados

Depois de inserir informações no banco, podemos precisar corrigir, atualizar ou excluir algum registro.

Os dois comandos principais para isso são:

  • UPDATE → alterar dados
  • DELETE → excluir dados

UPDATE

O que é?

O comando UPDATE altera dados que já existem em uma tabela.

Exemplo:

UPDATE inspecao_seguranca
            SET status = 'Resolvido'
            WHERE id = 5;

O que está acontecendo?

UPDATE inspecao_seguranca
                    ↓
            Qual tabela quero alterar?

            SET status = 'Resolvido'
                    ↓
            Qual informação quero modificar?

            WHERE id = 5
                    ↓
            Qual registro?

Nesse exemplo, somente o registro cujo id é 5 terá o status alterado.

Alterar várias colunas

Podemos alterar mais de uma coluna no mesmo comando. 

UPDATE inspecao_seguranca
            SET
                status = 'Resolvido',
                observacoes = 'Problema corrigido'
            WHERE id = 5;

Nesse caso, duas informações do mesmo registro serão alteradas.

Dica:

Separe cada alteração com uma vírgula.

⚠️ Cuidado com o WHERE

Essa é uma das coisas mais importantes para lembrar quando usamos UPDATE.

Seguro:

UPDATE inspecao_seguranca
            SET status = 'Resolvido'
            WHERE id = 5;

Apenas o registro com id = 5 será alterado.

Muito perigoso:

UPDATE inspecao_seguranca
            SET status = 'Resolvido';

Sem WHERE, o banco pode alterar todos os registros da tabela.

🧠 Regra do HoW to!:

Antes de executar um UPDATE, confira o WHERE.

DELETE

O que é?

Exclui registros da tabela.

Exemplo:

DELETE FROM inspecao_seguranca
            WHERE id = 5;

Nesse exemplo, o registro com id = 5 será excluído.

🚨 DELETE sem WHERE

Assim como no UPDATE, precisamos ter muito cuidado com o WHERE. 

DELETE FROM inspecao_seguranca;

Esse comando remove todos os registros da tabela.

A tabela continua existindo, mas seus registros serão removidos.

🧠 Regra do HoW to!:

UPDATE → cuidado com WHERE
            DELETE → cuidado com WHERE

UPDATE × DELETE

Comando O que faz?
UPDATE Altera dados existentes.
DELETE Remove registros. 
UPDATE
            ↓
            "Quero mudar alguma coisa."

            DELETE

Como alterar uma tabela

Depois que uma tabela já foi criada, podemos perceber que precisamos adicionar, remover ou modificar alguma coluna.

Para isso usamos o comando ALTER TABLE.

🧠 Primeiro: não confundir

Comando Altera o quê?
UPDATE Os dados dos registros.
ALTER TABLE A estrutura da tabela.

Exemplo:

Se quero mudar: 

status = 'Pendente'

uso UPDATE.

Se quero criar uma nova coluna chamada: 

prioridade

uso ALTER TABLE.

ADD — adicionar coluna

O que é?

Adiciona uma nova coluna a uma tabela existente.

Exemplo:

ALTER TABLE inspecao_seguranca
            ADD prioridade VARCHAR(20);

Agora a tabela passa a possuir a coluna prioridade.

Outro exemplo:

ALTER TABLE inspecao_seguranca
            ADD localizacao VARCHAR(100);

Dica:

Pense: ADD = adicionar.

DROP COLUMN — remover coluna

O que é?

Remove uma coluna da tabela.

Exemplo:

ALTER TABLE inspecao_seguranca
            DROP COLUMN prioridade;

A coluna prioridade deixa de existir.

⚠️ Os dados que estavam nessa coluna também serão perdidos.

Erro comum:

Confundir: 

DELETE

com: 

DROP COLUMN

DELETE remove registros.

DROP COLUMN remove uma coluna da estrutura.

MODIFY — modificar uma coluna

O que é?

Permite alterar a definição de uma coluna existente.

Exemplo:

Imagine que criamos: 

modelo VARCHAR(50)

e depois percebemos que precisamos de mais espaço. 

ALTER TABLE inspecao_seguranca
            MODIFY modelo VARCHAR(100);

Agora a coluna passa a aceitar até 100 caracteres.

Também podemos alterar regras:

ALTER TABLE inspecao_seguranca
            MODIFY modelo VARCHAR(100) NOT NULL;

Nesse caso, além do tamanho, estamos tornando a coluna obrigatória.

⚠️ Atenção:

Antes de modificar uma coluna, confira os dados que já existem nela. Uma alteração inadequada pode causar problemas ou perda de informação.

CHANGE — alterar nome e definição

O que é?

O CHANGE permite alterar o nome de uma coluna e também sua definição.

Exemplo:

ALTER TABLE inspecao_seguranca
            CHANGE modelo modelo_equipamento VARCHAR(100);

A coluna: 

modelo

passa a se chamar: 

modelo_equipamento

🧠 Diferença importante:

MODIFY
            ↓
            modifica a definição

            CHANGE
            ↓
            pode modificar o nome + definição

Exemplo completo

Imagine que a tabela já existe: 

inspecao_seguranca

E precisamos adicionar uma prioridade: 

ALTER TABLE inspecao_seguranca
            ADD prioridade VARCHAR(20);

Depois percebemos que precisamos aumentar o tamanho: 

ALTER TABLE inspecao_seguranca
            MODIFY prioridade VARCHAR(50);

E finalmente decidimos que o nome deveria ser nivel_prioridade: 

ALTER TABLE inspecao_seguranca
            CHANGE prioridade nivel_prioridade VARCHAR(50);

ADD Adicionar coluna.
DROP COLUMN Remover coluna.
MODIFY Modificar definição da coluna.
CHANGE Alterar nome e definição da coluna.

🔗 Relacionamentos entre tabelas

Em um sistema real, normalmente não colocamos tudo dentro de uma única tabela.

Criamos tabelas diferentes e fazemos com que elas possam se relacionar.

Exemplo no GatMan

usuarios
                │
                └── inspeções
                        │
                        └── manutenção

Uma inspeção pode estar associada a um usuário, e uma manutenção pode estar associada a uma inspeção.

FOREIGN KEY

O que é?

Uma FOREIGN KEY é uma chave utilizada para criar um relacionamento entre duas tabelas.

Enquanto a PRIMARY KEY identifica um registro dentro da própria tabela, a FOREIGN KEY permite apontar para um registro de outra tabela.

PRIMARY KEY × FOREIGN KEY

Tipo Função
PRIMARY KEY Identifica unicamente um registro.
FOREIGN KEY Cria uma ligação com outra tabela.

🧠 Pense assim: 

PRIMARY KEY
            ↓
            "Quem sou eu?"

            FOREIGN KEY
            ↓
            "Com quem estou relacionado?"

Exemplo simples

Imagine que temos uma tabela de usuários: 

CREATE TABLE usuarios (

                id INT AUTO_INCREMENT PRIMARY KEY,

                nome VARCHAR(100) NOT NULL

            ) ENGINE=InnoDB;

Agora queremos criar uma tabela de inspeções. 

CREATE TABLE inspecoes (

                id INT AUTO_INCREMENT PRIMARY KEY,

                descricao VARCHAR(200) NOT NULL,

                usuario_id INT,

                FOREIGN KEY (usuario_id)
                    REFERENCES usuarios(id)

            ) ENGINE=InnoDB;

O que está acontecendo?

usuarios
            │
            ├── id = 1
            │   └── Wagner
            │
            ├── id = 2
            │   └── João
            │
            └── id = 3
                └── Maria


            inspecoes
            │
            ├── id = 1
            │   └── usuario_id = 1
            │
            ├── id = 2
            │   └── usuario_id = 1
            │
            └── id = 3
                └── usuario_id = 2

A coluna usuario_id da tabela inspecoes aponta para a coluna id da tabela usuarios.

Portanto: 

inspecoes.usuario_id
                    ↓
            usuarios.id

REFERENCES

A palavra REFERENCES indica qual tabela e qual coluna serão referenciadas. 

FOREIGN KEY (usuario_id)
            REFERENCES usuarios(id)

Leia como:

A coluna usuario_id referencia o id da tabela usuarios.

🧠 Regra mental:

FOREIGN KEY
                ↓
            qual é a minha coluna?

            REFERENCES
                ↓
            qual tabela e coluna ela aponta?

JOIN

O que é?

O JOIN permite consultar informações que estão em tabelas diferentes.

Se temos: 

usuarios
            inspecoes

podemos fazer uma consulta que mostre dados das duas tabelas ao mesmo tempo.

INNER JOIN

O que é?

Retorna somente os registros que possuem correspondência entre as tabelas.

Exemplo:

SELECT
                inspecoes.id,
                inspecoes.descricao,
                usuarios.nome

            FROM inspecoes

            INNER JOIN usuarios
                ON inspecoes.usuario_id = usuarios.id;

O que aconteceu?

Estamos pegando: 

inspecoes
                ↓
            usuario_id

                    +

            usuarios
                ↓
            id

E dizendo ao banco: 

ON inspecoes.usuario_id = usuarios.id

Ou seja: "Relacione essas duas colunas quando os valores forem iguais."

Visualizando o resultado

Imagine que temos: 

usuarios

            id | nome
            ---|-------
            1  | Wagner
            2  | João
            3  | Maria
inspecoes

            id | descricao       | usuario_id
            ---|-----------------|-----------
            1  | Extintor        | 1
            2  | Porta corta-fogo| 1
            3  | Corrimão        | 2

Depois do JOIN: 

id | descricao        | nome
            ---|------------------|-------
            1  | Extintor         | Wagner
            2  | Porta corta-fogo | Wagner
            3  | Corrimão         | João

O banco juntou as informações das duas tabelas.

LEFT JOIN

O que é?

Retorna todos os registros da tabela da esquerda, mesmo quando não existe correspondência na tabela da direita.

Exemplo:

SELECT
                usuarios.nome,
                inspecoes.descricao

            FROM usuarios

            LEFT JOIN inspecoes
                ON inspecoes.usuario_id = usuarios.id;

Se um usuário ainda não tiver nenhuma inspeção, ele continuará aparecendo no resultado.

🧠 Pense assim:

INNER JOIN
            ↓
            quero somente os que possuem correspondência

            LEFT JOIN
            ↓
            quero todos da tabela principal,
            mesmo que não tenham correspondência

ON

O ON define a condição usada para relacionar as tabelas. 

INNER JOIN usuarios
                ON inspecoes.usuario_id = usuarios.id;

Nesse caso: 

inspecoes.usuario_id
                    =
            usuarios.id

Essa igualdade é o "elo" entre as duas tabelas.

GROUP BY

O que é?

O GROUP BY agrupa registros que possuem o mesmo valor em determinada coluna.

Ele é muito utilizado junto com funções como:

  • COUNT()
  • SUM()
  • AVG()
  • MIN()
  • MAX()

COUNT() + GROUP BY

Imagine que queremos saber quantas inspeções existem por status. 

SELECT
                status,
                COUNT(*) AS quantidade

            FROM inspecao_seguranca

            GROUP BY status;

O resultado poderia ser: 

status       | quantidade
            -------------|----------
            OK           | 25
            Pendente     | 8
            Atenção      | 4

Em vez de mostrar todas as inspeções individualmente, o banco agrupou os registros pelo campo status.

Funções de agrupamento

Função O que faz?
COUNT() Conta registros.
SUM() Soma valores.
AVG() Calcula uma média.
MIN() Encontra o menor valor.
MAX() Encontra o maior valor.

AS

O AS permite criar um nome temporário para uma coluna ou resultado. 

SELECT
                status,
                COUNT(*) AS quantidade

            FROM inspecao_seguranca

            GROUP BY status;

Nesse caso: 

COUNT(*)
                ↓
            resultado da contagem

            AS quantidade
                ↓
            nome que aparecerá no resultado

O AS não altera o nome da coluna no banco. Ele apenas dá um nome ao resultado daquela consulta.

HAVING

O que é?

O HAVING permite filtrar resultados depois que eles foram agrupados.

Ele é muito utilizado junto com GROUP BY.

WHERE × HAVING

Comando Filtra o quê?
WHERE Registros antes do agrupamento.
HAVING Grupos depois do agrupamento.

Essa diferença é muito importante.

Exemplo

Imagine que queremos descobrir quais status possuem mais de 5 inspeções. 

SELECT
                status,
                COUNT(*) AS quantidade

            FROM inspecao_seguranca

            GROUP BY status

            HAVING COUNT(*) > 5;

Primeiro o banco agrupa por status.

Depois o HAVING mantém somente os grupos cuja quantidade seja maior que 5.

🧠 Regra mental

WHERE
            ↓
            filtra registros

            GROUP BY
            ↓
            agrupa registros

            HAVING
            ↓
            filtra os grupos

🧠 Resumo dos relacionamentos

Comando Função
FOREIGN KEY Cria uma ligação entre tabelas.
REFERENCES Define para onde a chave aponta.
JOIN Combina dados de tabelas diferentes.
INNER JOIN Retorna correspondências entre tabelas.
LEFT JOIN Mantém todos os registros da tabela da esquerda.
GROUP BY Agrupa registros.
HAVING Filtra grupos.

🧠 Para lembrar

PRIMARY KEY
            ↓
            identifica

            FOREIGN KEY
            ↓
            relaciona

            JOIN
            ↓
            junta

            GROUP BY
            ↓
            agrupa

            HAVING
            ↓
            filtra grupos

🚀 Começar um projeto Git do zero

Quando temos uma pasta existente e queremos transformá-la em um repositório Git:

1️⃣ Entrar na pasta

cd caminho/da/pasta

No Windows, também podemos abrir o terminal diretamente dentro da pasta do projeto.

2️⃣ Inicializar o Git

git init

Cria o repositório Git dentro da pasta.

3️⃣ Conferir

git status

Mostra os arquivos modificados, novos arquivos e o estado atual do repositório.

⚙️ Configurar nome e e-mail

Normalmente fazemos essa configuração uma vez na máquina. 

git config --global user.name "Seu Nome"
            

            git config --global user.email "[seu@email.com](mailto:seu@email.com)"

Consultar as configurações

git config --global --list

O e-mail utilizado deve estar associado à conta do GitHub se quisermos que os commits sejam identificados corretamente nessa conta.

🐙 Associar a pasta ao GitHub

Depois de criar um repositório vazio no GitHub, podemos conectar a pasta local ao repositório remoto.

1️⃣ Adicionar o repositório remoto

git remote add origin URL_DO_REPOSITORIO

origin é o nome normalmente utilizado para representar o repositório remoto principal.

2️⃣ Conferir o endereço

git remote -v

Mostra para onde o Git está enviando e de onde está buscando os arquivos.

📤 Primeiro envio para o GitHub

1️⃣ Adicionar arquivos

git add .

2️⃣ Criar o commit

git commit -m "Primeiro commit"

3️⃣ Definir a branch principal

git branch -M main

4️⃣ Enviar para o GitHub

git push -u origin main

O -u estabelece a relação entre a branch local e a branch remota. Depois disso, normalmente podemos usar apenas: 

git push
