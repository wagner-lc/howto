🐈 Git & GitHub

O Git é o sistema que controla as versões dos arquivos do projeto.

O GitHub é um serviço onde podemos armazenar e compartilhar um repositório Git remotamente.

🚀 Começar um projeto Git do zero

Quando temos uma pasta existente e queremos transformá-la em um repositório Git:

1️⃣ Entrar na pasta

cd caminho/da/pasta

No Windows, também podemos abrir o terminal diretamente dentro da pasta do projeto.

2️⃣ Inicializar o Git

git init

Cria o repositório Git dentro da pasta.

3️⃣ Conferir

git status

Mostra os arquivos modificados, novos arquivos e o estado atual do repositório.

⚙️ Configurar nome e e-mail

Normalmente fazemos essa configuração uma vez na máquina. 

git config --global user.name "Seu Nome"
            

            git config --global user.email "[seu@email.com](mailto:seu@email.com)"

Consultar as configurações

git config --global --list

O e-mail utilizado deve estar associado à conta do GitHub se quisermos que os commits sejam identificados corretamente nessa conta.

🐙 Associar a pasta ao GitHub

Depois de criar um repositório vazio no GitHub, podemos conectar a pasta local ao repositório remoto.

1️⃣ Adicionar o repositório remoto

git remote add origin URL_DO_REPOSITORIO

origin é o nome normalmente utilizado para representar o repositório remoto principal.

2️⃣ Conferir o endereço

git remote -v

Mostra para onde o Git está enviando e de onde está buscando os arquivos.

📤 Primeiro envio para o GitHub

1️⃣ Adicionar arquivos

git add .

2️⃣ Criar o commit

git commit -m "Primeiro commit"

3️⃣ Definir a branch principal

git branch -M main

4️⃣ Enviar para o GitHub

git push -u origin main

O -u estabelece a relação entre a branch local e a branch remota. Depois disso, normalmente podemos usar apenas: 

git push

🔍 git status

git status

É provavelmente o comando que você mais deve usar.

Ele mostra o estado atual da pasta em relação ao último commit. 

git status
            

            ↓
            O que mudou?
            ↓
            O que está preparado?
            ↓
            Em qual branch estou?
            ↓
            Existe algo para enviar?

➕ git add

git add .

Adiciona as alterações ao chamado staging area.

Adicionar um arquivo específico

git add arquivo.php

Adicionar vários arquivos

git add arquivo.php
            

            git add arquivo.js
            git add css/estilo.css

🧠 Importante

git add ainda não cria o commit. Ele apenas prepara as alterações.

💾 git commit

git commit -m "Corrige salvamento da inspeção"

Cria uma nova versão do projeto contendo as alterações que estavam no staging.

Fluxo

Alterar arquivo
            ↓
            

            git add
            ↓
            Staging
            ↓
            git commit

            Nova versão local

📤 git push

git push

Envia os commits locais para o repositório remoto.

É o comando que normalmente usamos depois de terminar uma alteração e criar o commit.

📥 git pull

git pull

Busca alterações do repositório remoto e tenta integrá-las à branch atual.

🧠 Regra prática

GitHub mudou?
            

            ↓
            git pull
            ↓
            Minha pasta recebe as alterações

🌿 Branches

Uma branch é uma linha independente de desenvolvimento dentro do repositório.

Um modelo simples para o GatMan pode ser: 

main
            

            ↓
            versão principal / estável

            dev
            ↓
            desenvolvimento / testes

Ver todas as branches

git branch

Criar uma branch

git branch dev

Criar e entrar nela

git switch -c dev

🔄 Trocar entre main e dev

Ir para main

git switch main

Ir para dev

git switch dev

Ver onde estou

git branch

A branch atual aparece marcada com *. 

* dev
            

            main

🔀 Fluxo main ↔ dev

Uma maneira simples de trabalhar é desenvolver primeiro na dev e só depois levar o código estável para a main. 

main
            

            │
            │
            └──────→ dev
            │
            ├── alteração
            ├── teste
            ├── correção
            └── commit
            │
            ↓
            dev
            │
            │ quando estiver pronto
            ↓
            main

Começar o desenvolvimento

git switch dev

Fazer alterações

git add .
            

            git commit -m "Nova alteração"

Enviar a dev

git push origin dev

🔗 Merge — levar dev para main

Quando a dev estiver testada e pronta, podemos integrar suas alterações na main.

1️⃣ Ir para main

git switch main

2️⃣ Atualizar main

git pull

3️⃣ Fazer o merge

git merge dev

4️⃣ Enviar main para o GitHub

git push origin main

🧠 Resultado

dev
            

            ↓
            git merge dev
            ↓
            main
            ↓
            git push
            ↓
            GitHub

📜 Ver histórico

git log

Mostra o histórico dos commits.

Versão resumida

git log --oneline

🔎 Ver o que mudou

git diff

Mostra as alterações feitas nos arquivos que ainda não foram adicionadas ao staging.

É especialmente útil antes de fazer git add.

📥 Clonar um projeto existente

Se o projeto já existe no GitHub e queremos baixá-lo para uma máquina: 

git clone URL_DO_REPOSITORIO

O Git cria uma pasta contendo o projeto e seu histórico.
