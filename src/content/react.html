🧠 O que é React?

React é uma biblioteca JavaScript utilizada para criar interfaces.

Em vez de criar uma página inteira dentro de um único arquivo HTML, podemos dividir a interface em pequenas partes chamadas componentes. 

Home
↓
Header
↓
Categorias
↓
Footer

App
│
├── Header
│
├── Categorias
│   │
│   ├── CategoryCard
│   ├── CategoryCard
│   ├── CategoryCard
│   └── CategoryCard

📦 O que são Props?

Props são informações enviadas de um componente para outro.

Neste caso, o App.jsx envia informações para o CategoryCard.jsx.

📤 Enviando Props

As Props são enviadas através dos atributos do componente:

    link="js.html"

🔄 O que é map()?

O método map() percorre um array e executa uma função para cada item. Ele cria um novo array com os resultados retornados por essa função.

Exemplo simples, sem React: 

const numeros = [1, 2, 3]

const dobrados = numeros.map((numero) => {

    return numero * 2

})

O resultado de dobrados será: 

[2, 4, 6]

🧠 Regra mental

Array
   ↓
map()
   ↓
para cada item
   ↓
executa uma função
   ↓
guarda os resultados em um novo array

🏷️ Usando map() para criar os cards

No nosso caso, queremos que o map() percorra o array categorias e crie um CategoryCard para cada categoria.

Coloque este código dentro do return do App.jsx, no lugar onde os cards devem aparecer: 

{categorias.map((categoria) => (

    <CategoryCard

        key={categoria.titulo}

        icone={categoria.icone}

        titulo={categoria.titulo}

        descricao={categoria.descricao}

        link={categoria.link}

    />

))}

📤 Como as Props são enviadas?

Em cada volta do map(), a variável categoria representa um objeto diferente do array.

Por exemplo, na primeira volta: 

categoria.titulo
    ↓
HTML

Na segunda volta: 

categoria.titulo
    ↓
CSS

O React envia os valores desse objeto para o componente CategoryCard através das Props.

🔑 Para que serve key?

Quando criamos vários elementos com map(), o React precisa de uma identificação estável para cada elemento. Essa identificação é passada pela propriedade especial key. 

key={categoria.titulo}

Neste exemplo, usamos o título porque cada categoria tem um título diferente. A key ajuda o React a acompanhar os elementos da lista; ela não é uma Prop comum recebida pelo CategoryCard.

⬆️ Botões

Podemos criar um botão que aparece quando o usuário desce a página e permite voltar suavemente para o topo.

Esse é um bom exemplo de um componente React reutilizável, pois podemos colocá-lo em diferentes páginas da aplicação.

1️⃣ Criando o componente

Primeiro, criamos um novo componente: 

src/
            │
            └── components/
                └── ScrollToTop.jsx

2️⃣ Criando o componente

Dentro de ScrollToTop.jsx, importamos useState e useEffect: 

import { useState, useEffect } from 'react'

3️⃣ Controlando a visibilidade

Vamos utilizar useState para descobrir se o botão deve aparecer ou não. 

const [visivel, setVisivel] = useState(false)

Inicialmente, o botão não está visível: 

false

Quando o usuário rolar a página, poderemos alterar esse valor para true.

4️⃣ Detectando o scroll

Precisamos descobrir quando o usuário está rolando a página. Para isso, utilizamos o evento scroll.

O useEffect permite executar esse código quando o componente é carregado. 

useEffect(() => {

                function verificarScroll() {

                    if (window.scrollY > 300) {
                        setVisivel(true)
                    } else {
                        setVisivel(false)
                    }

                }

                window.addEventListener('scroll', verificarScroll)

            }, [])

Nesse exemplo, quando o usuário passar de 300 pixels do topo, o botão será exibido.

5️⃣ Removendo o evento

Quando o componente deixar de existir, devemos remover o evento que adicionamos anteriormente. 

return () => {
                window.removeEventListener('scroll', verificarScroll)
            }

O código completo do useEffect fica: 

useEffect(() => {

                function verificarScroll() {

                    if (window.scrollY > 300) {
                        setVisivel(true)
                    } else {
                        setVisivel(false)
                    }

                }

                window.addEventListener('scroll', verificarScroll)

                return () => {
                    window.removeEventListener('scroll', verificarScroll)
                }

            }, [])

6️⃣ Criando a função para voltar ao topo

Agora precisamos criar a função que será executada quando o usuário clicar no botão. 

function voltarAoTopo() {

                window.scrollTo({
                    top: 0,
                    behavior: 'smooth'
                })

            }

top: 0 significa voltar para o início da página.

behavior: 'smooth' faz com que a página suba suavemente em vez de pular diretamente para o topo.

7️⃣ Mostrando o botão

Se o botão não estiver visível, podemos simplesmente não renderizar nada: 

if (!visivel) {
                return null
            }

Quando visivel for true, o botão será criado: 

<button
                className="scroll-up"
                onClick={voltarAoTopo}
            >
                ↑
            </button>

8️⃣ Componente completo

Juntando tudo: 

import { useState, useEffect } from 'react'

            function ScrollToTop() {

                const [visivel, setVisivel] = useState(false)

                useEffect(() => {

                    function verificarScroll() {

                        if (window.scrollY > 300) {
                            setVisivel(true)
                        } else {
                            setVisivel(false)
                        }

                    }

                    window.addEventListener('scroll', verificarScroll)

                    return () => {
                        window.removeEventListener('scroll', verificarScroll)
                    }

                }, [])

                function voltarAoTopo() {

                    window.scrollTo({
                        top: 0,
                        behavior: 'smooth'
                    })

                }

                if (!visivel) {
                    return null
                }

                return (
                    <button
                        className="scroll-up"
                        onClick={voltarAoTopo}
                    >
                        ↑
                    </button>
                )

            }

            export default ScrollToTop

🧭 O que é React Router?

Quando trabalhamos com várias páginas em um site tradicional, normalmente temos vários arquivos HTML: 

index.html
            react.html
            php.html
            javascript.html
            git.html

Cada arquivo representa uma página diferente.

Em uma aplicação React, podemos utilizar o React Router para criar diferentes rotas dentro da aplicação.

Assim, em vez de navegar entre vários arquivos HTML, podemos utilizar URLs diferentes para mostrar diferentes componentes React.

🧠 Como funciona?

Podemos imaginar uma aplicação com as seguintes rotas: 

/
            ↓
            Página inicial

            /react
            ↓
            Página React

            /php
            ↓
            Página PHP

            /git
            ↓
            Página Git

Cada rota pode mostrar um componente diferente. 

/react
            ↓
            ReactPage

            /php
            ↓
            PhpPage

            /git
            ↓
            GitPage

📦 Instalando o React Router

Para utilizar o React Router, primeiro instalamos o pacote react-router-dom. 

npm install react-router-dom

Depois podemos importar os componentes necessários: 

import { BrowserRouter, Routes, Route } from 'react-router-dom'

🛣️ Criando uma rota

As rotas podem ser definidas utilizando Route. 

<Route
                path="/react"
                element={<ReactPage />}
            />

Nesse exemplo: 

path="/react"
            ↓
            define a URL

            element={<ReactPage />}
            ↓
            define o componente que será exibido

Portanto, quando o usuário acessar: 

http://localhost:5173/react

o React Router irá mostrar o componente: 

<ReactPage />

🧠 BrowserRouter, Routes e Route

Normalmente utilizamos os três juntos: 

<BrowserRouter>

                <Routes>

                    <Route
                        path="/"
                        element={<Inicio />}
                    />

                    <Route
                        path="/react"
                        element={<ReactPage />}
                    />

                </Routes>

            </BrowserRouter>

O BrowserRouter permite que a aplicação utilize o sistema de rotas do navegador.

O Routes agrupa as rotas da aplicação.

O Route define cada endereço e o componente correspondente.

🔗 Navegando entre páginas

Para criar links entre as rotas, podemos utilizar o componente Link. 

import { Link } from 'react-router-dom'

Depois podemos criar um link: 

<Link to="/react">
                React
            </Link>

Quando o usuário clicar no link, o React Router irá navegar para a rota correspondente.

⚠️ Link x <a>

Em um site HTML tradicional, normalmente usamos: 

<a href="/react.html">
                React
            </a>

Em uma aplicação React com React Router, utilizamos: 

<Link to="/react">
                React
            </Link>

O Link é próprio do React Router e permite navegar entre as rotas da aplicação sem precisar trabalhar com arquivos HTML separados.

🧠 No HoW to!

Antes da migração para React, o HoW to! possuía páginas separadas: 

index.html
            react.html

Agora podemos transformar essas páginas em componentes React: 

App

            ├── Inicio

            │
            ├── PhpPage
            │
            ├── JavascriptPage
            │
            └── GitPage

E criar uma rota para cada uma delas: 

/
            ↓
            Inicio

            /react
            ↓
            ReactPage

            ↓

            ↓

🎯 Exemplo completo

No nosso HoW to!, o App.jsx pode ficar responsável pelas rotas: 

import { BrowserRouter, Routes, Route } from 'react-router-dom'

            import Header from './components/Header'
            import ReactPage from './pages/React'

            function App() {

                return (

                    <BrowserRouter>

                        <Header />

                        <Routes>

                            <Route
                                path="/"
                                element={<Inicio />}
                            />

                            <Route
                                path="/react"
                                element={<ReactPage />}
                            />

                        </Routes>

                    </BrowserRouter>

                )
            }

            export default App

Dessa forma, a aplicação consegue controlar diferentes páginas utilizando rotas, enquanto continuamos trabalhando dentro da mesma aplicação React.

🛠️ React Router — Guia Prático

Vamos imaginar que temos uma aplicação React e queremos criar uma nova página chamada Example.

A ideia será criar esta URL: 

/example

E fazer com que ela mostre o componente: 

ExamplePage

1️⃣ Instalar o React Router

Primeiro, instalamos o React Router no projeto: 

npm install react-router-dom

2️⃣ Criar a página

Criamos um componente para representar nossa página.

Por exemplo, podemos criar: 

src/
            │
            ├── pages/
            │   └── ExamplePage.jsx
            │
            └── App.jsx

Dentro de ExamplePage.jsx: 

function ExamplePage() {

                return (
                    <main>
                        <h1>Página Example</h1>
                        <p>Esta é uma página de exemplo.</p>
                    </main>
                )

            }

            export default ExamplePage

Neste momento temos apenas um componente. Ainda não existe uma URL para acessá-lo.

3️⃣ Importar a página no App.jsx

Agora precisamos importar o componente que criamos: 

import ExamplePage from './pages/ExamplePage'

4️⃣ Importar o React Router

No App.jsx, importamos as ferramentas necessárias para trabalhar com rotas: 

import {
                BrowserRouter,
                Routes,
                Route
            } from 'react-router-dom'

5️⃣ Criar a rota

Agora podemos dizer ao React Router: 

Quando a URL for /example,
            mostre o componente ExamplePage.

Fazemos isso utilizando Route: 

<Route
                path="/example"
                element={<ExamplePage />}
            />

6️⃣ Colocar a rota dentro de Routes

As rotas ficam dentro de Routes: 

<Routes>

                <Route
                    path="/example"
                    element={<ExamplePage />}
                />

            </Routes>

7️⃣ Envolver as rotas com BrowserRouter

Por fim, colocamos o sistema de rotas dentro de BrowserRouter: 

<BrowserRouter>

                <Routes>

                    <Route
                        path="/example"
                        element={<ExamplePage />}
                    />

                </Routes>

            </BrowserRouter>

Agora temos a ligação: 

/example
                ↓
            Route
                ↓
            ExamplePage

8️⃣ Acessando a página

Se o projeto estiver rodando em: 

http://localhost:5173

podemos acessar: 

http://localhost:5173/example

E o React Router irá mostrar o componente ExamplePage.

9️⃣ Criando um link

Podemos criar um link para essa página utilizando o componente Link.

Primeiro importamos: 

import { Link } from 'react-router-dom'

Depois: 

<Link to="/example">
                Ir para Example
            </Link>

Quando o usuário clicar no link, o React Router irá navegar para: 

/example

🔟 Resumo do processo

Para criar uma nova página utilizando React Router: 

1. Criar o componente

            ExamplePage.jsx


            2. Importar o componente

            import ExamplePage from './pages/ExamplePage'


            3. Criar a rota

            <Route
                path="/example"
                element={<ExamplePage />}
            />


            4. Criar um link

            <Link to="/example">
                Ir para Example
            </Link>

🧠 Entendendo os nomes

É importante entender que cada nome representa uma coisa diferente: 

ExamplePage
            ↓
            Nome do nosso componente


            /example
            ↓
            Endereço (URL) da página


            Route
            ↓
            Define a relação entre URL e componente


            Link
            ↓
            Cria um link para uma rota


            BrowserRouter
            ↓
            Ativa o sistema de navegação


            Routes
            ↓
            Agrupa as rotas

🎯 A ideia principal

O conceito mais importante é este: 

URL
            ↓
            Route
            ↓
            Componente

Por exemplo: 

/example
            ↓
            Route
            ↓
            ExamplePage

E quando utilizamos um link: 

Link
            ↓
            /example
            ↓
            Route
            ↓
            ExamplePage

🚀 Publicar React/Vite no GitHub Pages

Quando um projeto React criado com Vite será publicado dentro de um repositório do GitHub, precisamos informar ao Vite qual será o caminho base do projeto.

1️⃣ Abrir o vite.config.js

O arquivo vite.config.js fica na raiz do projeto: 

howto/
                │
                ├── package.json
                ├── vite.config.js
                └── src/

2️⃣ Configurar o caminho base

No arquivo vite.config.js, adicionamos a propriedade base: 

import react from '@vitejs/plugin-react'
            import { defineConfig } from 'vite'

            export default defineConfig({
                plugins: [react()],
                base: '/howto/',
            })

3️⃣ O que significa base?

Se o repositório do GitHub se chama: 

howto

o GitHub Pages normalmente publicará o projeto dentro deste caminho: 

https://SEU-USUARIO.github.io/howto/

Por isso utilizamos: 

base: '/howto/'

O valor de base deve corresponder ao nome do repositório.

🎯 Resultado

O Vite agora sabe que os arquivos do projeto estarão dentro de /howto/ quando forem publicados no GitHub Pages.

🏗️ Criar o build do projeto

Antes de publicar o projeto no GitHub Pages, precisamos gerar a versão de produção da aplicação.

O Vite faz isso através do comando: 

npm run build

1️⃣ Abrir o terminal na pasta do projeto

Primeiro, precisamos estar dentro da pasta que contém o arquivo package.json. 

cd C:\Users\W\projects\howto\howto

2️⃣ Executar o build

Depois executamos: 

npm run build

3️⃣ O que o comando faz?

O Vite pega o código do projeto e cria uma versão otimizada para produção.

Essa versão será criada dentro da pasta: 

dist/

4️⃣ Estrutura criada

Depois do build, teremos algo parecido com: 

howto/
                │
                ├── src/
                ├── public/
                ├── package.json
                ├── vite.config.js
                │
                └── dist/
                    ├── index.html
                    └── assets/

🧠 Importante

A pasta dist contém a versão final que será utilizada para publicar o projeto.

Durante o desenvolvimento normalmente trabalhamos com: 

npm run dev

Para gerar a versão de produção utilizamos: 

npm run build

🎯 Resumo

Desenvolvimento
                    ↓
                npm run dev
                    ↓
                Projeto React


                Publicação
                    ↓
                npm run build
                    ↓
                pasta dist/

⚙️ Configurar o GitHub Actions

Podemos configurar o GitHub para gerar e publicar automaticamente o projeto React sempre que fizermos um push para o repositório.

1️⃣ Criar a pasta .github

Na raiz do projeto, criamos a pasta: 

.github/

2️⃣ Criar a pasta workflows

Dentro de .github, criamos: 

.github/
                └── workflows/

3️⃣ Criar o arquivo deploy.yml

Dentro da pasta workflows, criamos o arquivo: 

.github/
                └── workflows/
                    └── deploy.yml

4️⃣ Adicionar o workflow

Dentro de deploy.yml, colocamos: 

name: Deploy to GitHub Pages

            on:
            push:
                branches:
                - main

            permissions:
            contents: read
            pages: write
            id-token: write

            jobs:
            build:
                runs-on: ubuntu-latest

                steps:

                - name: Checkout
                    uses: actions/checkout@v4

                - name: Setup Node
                    uses: actions/setup-node@v4
                    with:
                    node-version: 22
                    cache: npm

                - name: Install dependencies
                    run: npm ci

                - name: Build
                    run: npm run build

                - name: Setup Pages
                    uses: actions/configure-pages@v5

                - name: Upload artifact
                    uses: actions/upload-pages-artifact@v3
                    with:
                    path: ./dist

                - name: Deploy
                    uses: actions/deploy-pages@v4

🧠 O que esse arquivo faz?

Esse arquivo diz ao GitHub o que fazer quando houver um push na branch main. 

git push
                ↓
            GitHub Actions
                ↓
            Instalar dependências
                ↓
            npm run build
                ↓
            Criar dist/
                ↓
            Enviar para GitHub Pages
                ↓
            Site publicado

🎯 Importante

Não precisamos enviar a pasta dist manualmente para o GitHub.

O próprio GitHub Actions irá executar: 

npm run build

e utilizará a pasta dist criada pelo Vite para realizar a publicação.

🔀 Enviar o projeto para a branch main

O GitHub Actions foi configurado para executar quando houver um push na branch main.

Como estamos trabalhando na branch dev, precisamos enviar as alterações da dev para a main.

1️⃣ Conferir a branch atual

Primeiro verificamos em qual branch estamos: 

git branch

A branch atual aparecerá marcada com um *. 

* dev
            main

2️⃣ Trocar para a main

Mudamos para a branch principal: 

git switch main

3️⃣ Atualizar a main

Antes de fazer o merge, é recomendado garantir que a versão local da main está atualizada: 

git pull origin main

4️⃣ Fazer o merge da dev

Agora incorporamos as alterações da dev na main: 

git merge dev

Se não houver conflitos, o Git fará o merge normalmente.

5️⃣ Enviar a main para o GitHub

Depois do merge, enviamos a main para o GitHub: 

git push origin main

🧠 O que acontece depois?

Como o workflow foi configurado para observar a branch main, o push irá iniciar o GitHub Actions. 

dev
            ↓
            merge
            ↓
            main
            ↓
            git push
            ↓
            GitHub Actions
            ↓
            npm run build
            ↓
            GitHub Pages

🎯 Resumo

git switch main

            git pull origin main

            git merge dev

            git push origin main
